# Sample Library

The sample library serves two jobs: it gives a new user a clear first
investigation, and it keeps Cobolens honest against source that was not written
for Cobolens. Every public corpus is checked in for offline use with its
upstream Apache-2.0 license and an exact source revision.

Counts are generated by the current Rust sidecar and deliberately include
lightweight fallback output. A warning means tree-sitter found an unsupported or
ambiguous construct and the lightweight scan still produced graph evidence; it
does not mean the file was dropped.

## Redistribution and scope

The three upstream repositories use Apache-2.0. Their unmodified COBOL,
copybook, and JCL files are retained under `samples/catalog/` together with the
upstream license and a README naming the source repository and pinned commit.

Only analyzer-relevant source is bundled. CardDemo data, archives, generated
binaries, assembler, BMS, and deployment material are excluded. This keeps the
offline library reviewable and avoids pretending Cobolens understands file
types it does not scan.

## Regeneration

Build the debug analyzer, then regenerate every public graph/source pair:

```sh
cargo build --manifest-path sidecar/cobolens-analyze/Cargo.toml
npm run samples:build
node tools/m6-verify/sample-library-smoke.mjs
```

`sample-library-smoke.mjs` checks graph counts, referenced source coverage,
byte-for-byte source-bundle parity, license retention, and pinned provenance.

## Hardening findings

- Real IBM source exposes 31 visible fallback warnings across the three public
  scenarios. Parse Health keeps them inspectable instead of converting them to
  a green success claim.
- Switching from a long Source view initially blanked the React workspace. The
  sample loader now keeps the current graph mounted until the replacement is
  ready and returns the canvas to Map before the swap.
- The existing Guided Trace `<details>` surface collapsed to two CSS pixels in
  a constrained navigator. Its content looked present to accessibility tools
  but pointer hits landed on the parent. The container now uses max-content
  sizing and every guide target is resolved against the loaded graph.
- The first CardDemo pass loaded in 5.1–5.6 seconds and mounted all 272
  source-tree controls. The second hardening loop bounds eager semantic work to
  the 160 chunks the feature can use and shows 12 entries per expanded source
  group. The same local development flow reached a usable map in about 0.82
  seconds with 13 inventory controls mounted.
- Public source exposed false graph relationships from fixed/free-format
  comments, quoted display literals, and CICS `READ FILE(...)` syntax. The
  analyzer now preserves quoted operands when they are meaningful (for example
  `CALL 'PAYCALC'`) while excluding prose and literal moves from dependency
  nodes. The four pinned corpora lock this behavior in as a regression.
- All 190 bundled source files remain usable. The public projects still expose
  31 honest tree-sitter fallback warnings (7 IBM batch, 1 z/OS Connect, 23
  CardDemo); these represent dialect/syntax coverage still to improve, not
  dropped files.
- The large Source file switcher still contains every source file in one native
  select. Symbol search and the grouped navigator are the preferred path today;
  a filtered file switcher is a future scale improvement.

The detailed second-loop evidence and remaining limits are recorded in
[the hardening audit](audits/hardening-loop-2-2026-08-31/AUDIT.md).
